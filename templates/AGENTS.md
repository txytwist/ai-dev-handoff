# Project agent instructions

先读取本仓库 PROJECT_CONTEXT.md、已有规则、当前任务和最新交接，报告实际读取的 ref。保留已有程序与规范；本文件应合并接入，不覆盖已有 AGENTS.md。

只在批准范围和此项目功能分支工作。任务 PLANNED 等用户批准后才执行；记录 APPROVED、IN_PROGRESS、REVIEW，返工为 CHANGES_REQUESTED，用户接受才 ACCEPTED。

Issue 不可读时要求完整正文或 docs/tasks/ 文件。先保存完整任务及批准证据到 docs/tasks/ 再实施。实际运行适用检查，未运行如实报告。任务与代码一起留在 GitHub。

提交 PR 和 docs/handoff/ 记录：来源、基线、分支、验证 ref、文件、命令结果、限制与下一步。用户主动返回 ChatGPT 审核；审核不等于合并许可。不能推送/创建 PR 则报告阻塞，不伪造链接。

不要自行合并、部署、发布、删数据、公开仓库或修改其他项目。不要提交秘密，不声称聊天自动同步或自动唤醒。许可由所有者决定。

## 每次新会话的默认 Skill 执行

新项目默认继承 caveman 和 ponytail，每次新会话必须主动读取 `.agents/skills/caveman/SKILL.md` 与 `.agents/skills/ponytail/SKILL.md` 的完整正文并执行适用于本轮的指令，不等用户另行请求。先核对用户当前指令及 PROJECT_CONTEXT.md 中明确记录的禁用决定；只有用户明确禁用的 Skill 才跳过，记录禁用范围，不能把未指定当成禁用。

加载失败（文件缺失、不可读、解析错误、原生调用不可用）必须报告具体 Skill、路径/原因、受影响步骤和未验证项，不得静默跳过或伪称执行。宿主不能原生调用但能读取时，明确标记“按文件指令执行”，不冒充原生激活；无法读取时暂停依赖该 Skill 的步骤，按已有安全/授权规范处理任务。

交接分别记录原生发现、正文读取、实际执行证据、新会话自动激活状态；发现或文件存在不等于实际执行。本规则是每次会话主动加载的要求，不是自动激活已经实测的声明。

简短风格和最小改动不能削弱原有开发、安全、测试、授权与交接规范；持久文档保持完整清晰。用户语言/回复格式和更高优先级规则仍优先。禁止擅自安装上游hooks、代理、遥测或全局配置。
